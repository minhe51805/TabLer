# TableR v0.1.6

TableR v0.1.6 closes the last professional-workflow gaps from the v0.1.5 baseline and adds the first five differentiator features on top: a unified grid editing model, bounded streaming imports, PII masking, plan-driven index proposals, generated schema documentation, scheduled queries, and a visual query builder.

## Highlights

- unified DataGrid range editing: copy/paste/delete/fill-down over rectangular selections, staged as one atomic undo/redo batch behind the existing review modal
- bounded streaming CSV import for the Tools → Import CSV wizard: 8 KB delimiter sniffing, one-pass bounded preview, per-batch progress events, cancellation, and a 10 GB sanity cap replacing the old 100 MB full-file gate
- anonymized clipboard exports: per-column masking strategies (SHA-256 hash, redact, NULL, fake email/name/phone, numeric noise) with stable salt support and a primary-key protection guard
- index advisor: full-scan nodes from EXPLAIN plans become ready-to-review CREATE INDEX statements with cost/row reasoning; Postgres-style "Relation Name"/"Index Name" plan details now surface correctly in the visualizer
- auto database documentation: deterministic Markdown and printable HTML schema books with a relationship summary, per-table column grids, indexes, and foreign keys
- scheduled saved queries: a minute-tick Rust scheduler runs single SELECT/WITH statements on 5-minute to 7-day intervals with persisted run status, failure recording, and toast notifications; destructive or multi-statement SQL can never be scheduled
- visual SELECT query builder: tables, typed joins, filters, aggregates with GROUP BY/HAVING, and named locally persisted definitions — the compiled statement always opens as editable SQL in a query tab
- AI panel hardening: a persisted-workspace sanitizer drops malformed bubbles/attachments instead of crashing the panel

## Upgrade and recovery

No storage schema changes ship in v0.1.6. The scheduler creates `query_schedules.json` beside the existing storage files on first run, and the query builder persists definitions under the browser-origin storage key `tabler.builder-definitions.v1`. See `docs/operations/STORAGE_RECOVERY.md` before manually changing application data.

## Release gates

The GitHub release must remain draft until the platform assets, updater metadata, and a scheduler smoke drill (create → fire → cancel → delete) have produced immutable evidence. The final release must be non-draft, non-prerelease and marked Latest only after that verification.
